# NYC Restaurant Health Inspections — Data Cleaning

A standalone capstone project applying the techniques from Kaggle's **Data Cleaning**
course to a realistically messy restaurant-inspection dataset.

## The problem

A city health department's inspection export has the usual real-world mess:
- Inconsistent casing/whitespace in `borough` and `cuisine_type` (`"manhattan"`, `" Manhattan "`, `"MANHATTAN"`)
- Four different date formats mixed in the same column
- Impossible inspection scores (`-5`, `999`)
- A numeric column (`violations_count`) with a stray text value and missing entries
- Duplicate inspection records
- Missing restaurant names and grades

## What this project does

`notebooks/data_cleaning_restaurant_inspections.ipynb` walks through, step by step:

1. Scoping every data quality issue before touching anything
2. Removing exact duplicates
3. Standardizing inconsistent text categories
4. Parsing mixed date formats
5. Fixing a mixed-type numeric column
6. Detecting and handling out-of-range outliers
7. Imputing/flagging missing values transparently (not silently)
8. Validating the final dataset with explicit assertions
9. Saving a clean, analysis-ready CSV

## Run it yourself

```bash
pip install -r requirements.txt
python data/generate_raw_data.py        # regenerate the raw data (optional, already included)
jupyter notebook notebooks/data_cleaning_restaurant_inspections.ipynb
```

## Why synthetic data?

The dataset is generated by `data/generate_raw_data.py` to mirror the structure and the
*exact kinds* of mess found in the real
[NYC Restaurant Inspection Results](https://www.kaggle.com/datasets/new-york-city/nyc-restaurant-inspection-results)
dataset on Kaggle, so the whole project runs fully offline and reproducibly — no download
or API key required. Swap in the real CSV and the same cleaning logic applies with minor
column-name tweaks.
